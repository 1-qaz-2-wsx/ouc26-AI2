## 1.4 IDA* 算法

### 1.4.1 基本思想

IDA*（Iterative Deepening A*）把 A* 的估价函数与迭代加深的深度优先搜索结合起来。设
g(n) 为从初始状态到结点 n 的实际代价，h(n) 为 n 到目标的启发估计，f(n)=g(n)+h(n)。
IDA* 不维护全局优先队列，而是在每一轮给定一个阈值 limit，只对 f(n)≤limit 的结点做
深度优先搜索；本轮没有到达目标时，把本轮遇到的所有被剪掉结点中最小的 f 值作为下一轮
阈值。初始阈值取 h(初始状态)，阈值随轮次单调增加。

与 A* 每次从 Open 表取出全局最小 f 不同，IDA* 的搜索顺序是深度优先的，因此它不需要
保存整个 Open/Closed 表，空间开销主要取决于当前路径深度；代价是同一批状态可能在相邻
阈值轮中被重复展开。

### 1.4.2 阈值更新与终止

每轮搜索返回两类信息：是否到达目标，以及本轮所有 f(n)>limit 的结点中最小的 f 值。
若没有到达目标，就把该最小值作为下一轮阈值。这样下一轮不会漏掉任何 f 值介于新旧阈值
之间的结点，也不会像“阈值加一”那样做无意义的空轮。若整棵搜索树都没有更大的 f 值，
说明状态空间已经搜索完毕且目标不可达，搜索返回无解。

本实现还提供时间上限和结点数上限：达到上限时中断搜索，并通过 aborted() 标记返回。
调用方必须把这种情况记为 TIMEOUT，而不能记为 UNSOLVABLE，避免把“没算完”误报成
“无解”。

### 1.4.3 路径恢复

框架中的 Node 保存了 parent、action 和 pathCost。命中目标后，沿着 parent 指针回溯即可
得到从初始状态到目标的动作序列。AbstractSearcher.generatePath 返回的队列不含根结点，
因此导出 NP_PATH_V1 路径文件时，需要把初始棋盘单独作为第 0 帧写入；路径长度等于
目标结点的 pathCost，在单位代价问题中也就是步数。

### 1.4.4 可采纳性与最优性

称启发函数 h 可采纳，是指对任意状态 n 都有 h(n)≤h*(n)，其中 h*(n) 是 n 到目标的
真实最小代价。设最优解代价为 C*。当阈值 limit<C* 时，任何目标结点的 f 值都等于其
路径代价，至少为 C*，因此不可能被本轮接受；当阈值增长到 C* 时，最优路径上的每个
结点都满足 f(n)=g(n)+h(n)≤g(n)+h*(n)=C*，搜索能够沿该路径到达目标。第一次被接受
的目标结点满足 g(goal)≤limit，而此前所有阈值都小于 C*，所以该解的代价只能是 C*。
因此 h 可采纳时，IDA* 返回的第一个解就是最优解。

可采纳性保证最优性；一致性（单调性）不是 IDA* 正确性的必要条件，但一致的启发函数
可以避免同一路径上的重复估值，并让置换表的剪枝更稳定。本实验使用的曼哈顿距离和
不相交模式数据库都满足可采纳性，PDB 的加性构造在组长章节中单独证明。

### 1.4.5 复杂度与优缺点

IDA* 的时间复杂度与启发函数质量、阈值轮数和每轮展开的结点数有关，最坏情况下仍是指数
级；启发函数越强，阈值增长越快，重复展开越少。空间复杂度在没有置换表时主要与搜索深度
相关，明显低于 A* 的 Open/Closed 表。

IDA* 的优点是空间开销小、实现简单、不依赖优先队列，适合内存紧张或启发函数较强的
15-Puzzle 搜索；缺点是对同一状态可能重复展开，且每轮都要重新从根开始，弱启发函数下
时间开销会迅速增大。A* 在内存充足、启发函数较弱时通常更稳定；IDA* 在强启发函数和
受限内存下更有优势。本实验的 15-Puzzle 难例说明：即使使用正式 PDB，单纯 IDA* 仍可能
在 60 秒内无法完成，算法优化不能替代启发函数质量。

### 1.4.6 本实现的工程选择

本实现保留框架要求的 Frontier 构造参数，但 IDA* 本身不使用优先队列，实际传入的是
StackFrontier；搜索状态、阈值轮数、生成/扩展结点数都由搜索器统一统计。反向移动剪枝
和 Zobrist 置换表作为可开关选项，默认只开启反向移动剪枝，便于在同一测试入口中做优化
前后的对照实验。置换表按轮清空，只记录当前阈值下各状态已访问的最小 g 值，具体正确性
说明见 4.2 节。
