# 5. 解路径的可视化

## 5.1 工具与环境

本项目的可视化模块采用 C++ 语言与 SFML (Simple and Fast Multimedia Library) 2.6 版本开发。SFML 提供了跨平台的窗口管理、图形渲染与事件处理机制，能够高效地实现 2D 棋盘动画的平滑播放。该模块旨在将抽象的解路径数据转化为直观的视觉动画，以便测试人员验证搜索算法的正确性与路径合法性。

## 5.2 关键逻辑与数据结构设计

1. **文件解析与输入校验**：程序通过读取 `NP_PATH_V1` 格式的纯文本文件，利用文件流逐行解析元数据（如棋盘大小 `size`、求解状态 `status`、总步数 `moves`）以及每一帧的棋盘数组。程序包含严格的数据校验机制，确保输入的棋盘排列合法且不存在非法跃迁。
2. **自适应渲染策略**：UI 布局采用动态计算策略。根据解析出的棋盘大小 `size`（3 或 4），动态计算每个滑块（Tile）的边长与坐标偏移量，确保 3x3 与 4x4 棋盘均能居中且美观地展示在窗口中央。
3. **动画与事件驱动**：利用 `sf::Clock` 实现定时器，每隔 0.5 秒自动切换至下一帧（State），从而形成滑块移动的动画效果。底层播放状态（播放、暂停、单步）与图形渲染解耦，确保状态切换的稳定性。
4. **多题目管理**：程序支持自动遍历指定目录下的所有 `.txt` 路径文件，并按照文件名进行排序，方便测试人员在不同测试用例之间快速切换。

## 5.3 异常与特殊状态处理

程序针对不同的测试结果进行了专门的异常处理与界面反馈：

*   **UNSOLVABLE（无解）**：当读取到状态为无解的文件时，程序将停留在第 0 帧（初始状态），禁止自动播放，并在状态栏高亮显示。
*   **零步（已解）**：对于初始状态即目标状态的题目，程序直接显示目标画面，不播放动画。
*   **非法文件**：若文件格式错误、缺少字段或存在非法跳跃，程序会拒绝加载并打印具体错误行号，防止错误数据导致程序崩溃。

## 5.4 界面布局与交互展示

为了直观地验证 N-Puzzle 算法求解路径的正确性，可视化界面被划分为三个主要区域：

1. **顶部状态栏**：实时显示当前正在播放的解路径文件名、该题目的求解状态、当前播放步数/总步数（如 `Step 0/70`）以及当前的播放速度。
2. **中央棋盘区**：自适应渲染对应数量的数字滑块。其中空位（数字 0）用深灰色方块表示，数字滑块以蓝色背景及白色数字居中显示，确保视觉清晰。
3. **底部操作栏**：提供完整的鼠标控制按钮（播放/暂停、上下单步、切换题目、调速等），并在最下方常驻显示快捷键提示，降低使用者的学习成本。

## 5.5 测试结果与验证逻辑

本播放器不仅是动画展示工具，也是算法结果的第一道“质检关卡”。测试人员利用该播放器对算法导出的路径文件进行逐一验证：

1. **合法性检查**：通过逐帧播放（单步控制），确认每一步移动是否仅交换了空位与相邻数字，是否存在“穿墙”或非法跳跃。
2. **目标状态校验**：播放至最后一帧时，视觉确认棋盘是否完全还原为目标状态。
3. **无解判断一致性**：针对输入的无解题目，确认界面是否正常阻止了动画播放，并正确显示无解标识。
