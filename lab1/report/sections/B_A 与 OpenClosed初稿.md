# 1. 启发式算法综述

## 1.1 算法描述

A* 是一种启发式最佳优先搜索算法。它同时考虑从初始状态到当前结点的实际路径代价，以及从当前结点到目标状态的估计代价。评价函数定义为：

$$
f(n)=g(n)+h(n)
$$

其中，\(g(n)\) 表示从初始状态到结点 \(n\) 的实际代价，\(h(n)\) 表示从结点 \(n\) 到目标状态的估计代价，\(f(n)\) 表示经过结点 \(n\) 到达目标状态的估计总代价。

N-Puzzle 中每次合法移动的代价为 1，因此 \(g(n)\) 等于从初始棋盘到当前棋盘的移动次数。

A* 使用 Open 表保存已经生成但尚未扩展的候选结点，使用 Closed 表记录已经扩展的状态。搜索开始时，将初始状态加入 Open 表。之后反复取出 \(f\) 值最小的有效结点：若其为目标状态，则沿父结点引用恢复解路径；否则登记为已扩展状态，并生成其合法后继。

算法基本过程如下：

```text
输入：初始状态 s、目标状态 goal、启发函数 h
输出：从 s 到 goal 的最优解路径，或无解

1. 判断问题是否可解；若不可解，返回无解。
2. 创建初始结点，令 g(s)=0，计算 h(s) 和 f(s)。
3. 将初始结点加入 Open 表。
4. 当 Open 表非空时：
   4.1 取出 f 值最小的有效结点 n。
   4.2 若 n 为目标结点，根据父结点引用恢复路径并返回。
   4.3 登记 n 的状态及其路径代价。
   4.4 生成 n 的合法后继，并计算其 g、h 和 f。
   4.5 根据 Open 和 Closed 中的 best-g 信息处理重复状态。
5. 若 Open 表为空仍未找到目标，则返回无解。
```

N-Puzzle 的状态空间是图而不是树。同一棋盘可能通过不同动作序列到达，因此算法需要处理 Open 表中的重复候选、已经扩展的状态，以及发现更优路径后重新打开状态的情况。

## 1.2 算法的可采纳性

### 1.2.1 A* 算法

设 \(h^*(n)\) 表示状态 \(n\) 到目标状态的真实最小代价。若启发函数对所有状态均满足：

$$
0\leq h(n)\leq h^*(n)
$$

则称该启发函数具有可采纳性。可采纳启发函数可以低估真实代价，但不能高估；它可能导致搜索额外结点，却不会因估值过高而排除最优解。

本实验使用的三种启发函数均具有可采纳性：

1. **错位将牌数**：每个错位数字至少需要移动一次，因此错位数字数不超过真实剩余步数。
2. **曼哈顿距离**：每个数字至少需要移动其当前位置与目标位置之间的行列距离；忽略数字之间的阻挡只会低估真实代价。
3. **Disjoint Pattern Database**：数据库保存抽象状态的精确最短距离。不同模式组使用互不重叠的数字集合，并采用代价划分避免对同一步移动重复计费，因此各组距离之和不超过真实代价。

### 1.2.2 A* 算法可采纳性证明

设最优解代价为 \(C^*\)。在 A* 找到目标状态之前，Open 表中至少存在一个位于最优路径上的结点 \(n\)。由于启发函数可采纳：

$$
h(n)\leq h^*(n)
$$

因此：

$$
f(n)=g(n)+h(n)\leq g(n)+h^*(n)=C^*
$$

设 A* 取出的目标结点为 \(G\)。目标状态的启发值为 0，因此：

$$
f(G)=g(G)
$$

A* 总是取出 Open 表中 \(f\) 值最小的有效结点，所以：

$$
g(G)=f(G)\leq f(n)\leq C^*
$$

另一方面，任何从初始状态到目标状态的路径代价都不小于最优代价：

$$
g(G)\geq C^*
$$

因此：

$$
g(G)=C^*
$$

A* 返回的解为最优解。对于图搜索，重复状态处理还必须正确保留更优路径；本实验通过 Open/Closed best-g 规则及必要的 reopen 处理状态更新。

## 1.3 重复扩展结点的问题

### 1.3.1 重复扩展结点问题

N-Puzzle 中存在大量重复状态。例如，空格移动后立即反向移动会回到原状态，不同的动作序列也可能到达同一棋盘。

如果不处理重复状态，可能导致：

1. 相同状态多次进入 Open 表；
2. 较差路径占用额外内存；
3. 状态被重复扩展并生成更多重复后继；
4. 搜索时间和空间消耗增加。

对于同一状态 \(s\)，若：

$$
g_1(s)<g_2(s)
$$

则路径代价较小的路径更优，算法应拒绝或替换较差路径。

仅使用 Closed 集合记录“是否扩展过”无法比较到达同一状态的不同路径代价。因此，图搜索还需要处理 Open 中的重复候选、Closed 中的最优 \(g\)，以及发现更优路径后的 reopen。

### 1.3.2 启发函数的单调性

若对任意状态 \(n\) 及其后继 \(n'\) 满足：

$$
h(n)\leq c(n,n')+h(n')
$$

则称启发函数具有单调性，也称一致性。由于：

$$
g(n')=g(n)+c(n,n')
$$

可得：

$$
\begin{aligned}
f(n') &= g(n')+h(n')\\
&=g(n)+c(n,n')+h(n')\\
&\geq g(n)+h(n)\\
&=f(n)
\end{aligned}
$$

因此，使用一致启发函数时，沿路径的 \(f\) 值不会下降；状态第一次以有效结点形式从 Open 表取出时，通常已经具有最小 \(g\)。

错位将牌数和曼哈顿距离在一次合法移动后最多下降 1，而移动代价为 1，因此满足一致性条件：

$$
h(n)\leq 1+h(n')
$$

Disjoint Pattern Database 使用互不重叠的模式组和代价划分。每个模式数据库中的抽象最短距离满足三角不等式，各模式组代价相加后不超过一次真实移动的代价，因此其和也满足一致性条件。

本实验保留 Closed best-g 和 reopen 机制，以支持将来接入可采纳但不一致的启发函数。

# 3. N-Puzzle 求解算法实现

## 3.2 Open 表及 Closed 表的数据结构

### 3.2.1 Open 表

Open 表以 Java `PriorityQueue` 为核心，按照：

$$
f(n)=g(n)+h(n)
$$

对结点排序。插入和取出堆顶结点的时间复杂度通常为 \(O(\log n)\)。

`PriorityQueue` 不支持根据状态快速查找结点，也不支持高效的 decrease-key。实现中使用状态索引：

```java
Map<State, Set<Entry>> pending
```

保存 Open 表中各状态的有效条目。启用 Open best-g 时，如果新结点的 \(g\) 不优于已有结点，则拒绝新结点；如果更优，则使旧条目失效并加入新结点。

由于从优先队列中删除任意位置的旧条目需要线性查找，本实现采用延迟删除：旧条目暂时留在堆中，到达堆顶时再检查有效性并跳过。

这种方式使状态查询平均为 \(O(1)\)，避免了任意位置删除；代价是过期条目会暂时占用堆空间，并需要在取出时检查有效性。

### 3.2.2 Closed 表

基础 Closed 表可使用：

```java
Set<State>
```

记录状态是否已经扩展，但不能记录路径代价。优化实现使用：

```java
Map<State, Integer> closedBestG
```

记录每个已扩展状态的最小 \(g\)。

生成后继时，如果 Closed 中已有不大于新路径代价的记录，则舍弃新路径；如果新路径的 \(g\) 更小，则移除旧记录并重新加入 Open 表，即 reopen。

对于一致启发函数，reopen 通常不会发生；对于可采纳但不一致的启发函数，该机制可以避免状态被较差路径过早关闭。

### 3.2.3 对比配置

实验实现四种配置：

| 配置             | Open best-g | Closed best-g | 延迟删除 | Reopen |
| ---------------- | ----------- | ------------- | -------- | ------ |
| `BASELINE`       | 否          | 否            | 否       | 否     |
| `OPEN_BEST_G`    | 是          | 否            | 是       | 否     |
| `CLOSED_BEST_G`  | 否          | 是            | 否       | 是     |
| `FULL_OPTIMIZED` | 是          | 是            | 是       | 是     |

四种配置均使用 `PriorityQueue`，因此实验比较的是重复状态处理策略，而不是顺序表与优先队列的差异。`FULL_OPTIMIZED` 同时使用 Open 和 Closed best-g，是最终优化配置。

# 4. N-Puzzle 问题求解探讨

## 4.1 Open 表及 Closed 表数据结构的改进及其对算法性能的影响

### 4.1.1 实验目的

本实验主要验证：

1. Open best-g 是否保留同一状态的较短路径；
2. Closed best-g 是否正确记录已扩展状态的最小 \(g\)；
3. 过期结点是否能被跳过；
4. reopen 是否能处理 Closed 状态的更优路径；
5. 不同重复状态处理方式对运行时间和搜索规模的影响。

### 4.1.2 实验方法

实验采用两个 8-Puzzle 实例，两个实例的最优解长度均为 31。Open/Closed 对比统一使用曼哈顿距离；启发函数对比统一使用 `FULL_OPTIMIZED` 模式。

阶段二和阶段三实验均先预热，再对每种配置正式运行 10 次，以运行时间中位数作为结果。正确性测试输出为：

```text
ALL PASS: 123 Phase2 A* checks
```

阶段二与阶段三分别生成原始 CSV 和汇总 CSV。以下主表采用最新的 `astar-phase2-summary.csv`；阶段三复测的结点数和解长度一致，运行时间有小幅波动，因此两批时间不混合计算。

### 4.1.5 结果分析

实验表明，重复状态处理显著影响搜索规模。`FULL_OPTIMIZED` 相较 `BASELINE` 将扩展结点数减少约 99.16%，中位运行时间从约 4.95—5.17 秒降至约 23 ms。

启发函数也明显影响搜索效率。错位将牌数提供的信息较少，扩展结点最多；曼哈顿距离进一步考虑数字到目标位置的行列距离；Disjoint Pattern 使用抽象状态的精确距离，扩展结点最少。本次实验中，Disjoint Pattern 的运行时间约为 5.9 ms，低于曼哈顿距离和错位将牌数。

Open/Closed 优化的主要作用是保留更优路径、过滤重复和过期结点，并支持必要的 reopen。三种启发函数在两个实例上均返回长度为 31 的合法解，说明性能差异没有改变最终解的长度。

Disjoint Pattern 数据库文件大小为 6552 bytes。阶段二和阶段三日志均记录了 PDB 准备及后续读取过程。实验结果支持以下结论：Open/Closed 表优化能够显著减少重复搜索；更强的启发函数能够进一步缩小搜索空间。
