# 协作与开发环境

## Git 仓库与原始版本

Git 根目录为 `AI2`，IDEA 打开 `lab1/WattAi`。默认分支为 `main`。后续 lab2 直接加入同一仓库，各组员继续使用当前克隆目录。

`course-baseline` 保存首次建立仓库时的课程源码、输入文件及文档，源码保留原字节。它不是压缩包刚发布时的全部目录快照：忽略个人 IDEA 设置、旧编译产物，`WattAi.iml` 则保留。

Git 已配置仓库级 `core.autocrlf=false`，避免原始混合编码源码首次提交被换行转换。组员克隆后执行 `git config core.autocrlf false`；此设置无需修改全局 Git 配置。

查看原始文件可使用 `git show course-baseline:WattAi/src/core/runner/EngineFeeder.java`。标签保留迁移前的树结构，因此这里没有 lab1 前缀；当前主分支使用 lab1/WattAi。需要另行查看基线时，导出到新目录，不覆盖工作目录。本地另有 `lab1/.local/course-baseline.zip`，不上传。

## 日常操作

首次领取任务，在克隆目录中执行：

```powershell
git config core.autocrlf false
git switch main
git pull --ff-only origin main
git switch -c feature/model
```

最后一条替换为自己的分支名。若远程已存在自己的分支，使用 `git switch --track origin/feature/model`，不要再次新建同名分支。

完成可检查的小功能后，检查 `git status`，只添加本人改动的明确文件，提交并推送；第一次使用 `git push -u origin feature/model`，之后 `git push`。通过平台创建合并请求，目标为 `main`。

开发过程中先提交或暂存本人的工作，再执行 `git fetch origin` 和 `git merge origin/main` 同步公共变更；遇到冲突保留双方意图并协调，不以整份文件覆盖处理。组长检查测试与接口后合并，无需每个人直接推送 `main`。

合并请求说明写四项：改动文件、运行方式、测试证据、未完成问题。多人不要同时编辑最终 Word；各自章节先放 `report/sections`，组长合稿。

## IDEA 与运行配置

1. Project SDK 为 JDK 25；模块 SDK 继承项目设置，语言级别 25，不启用 preview。
2. 新文件 UTF-8，原文件按实际编码打开；详见编译记录。全工程直接指定 UTF-8 或 GB18030 都不能解决原始混合编码。
3. 第一阶段主类为 `core.runner.SearchTester`，工作目录为各自电脑上的 `WattAi`。
4. 预期参数：`resources/problems.txt NPUZZLE 1 stud.g01.runner.PuzzleFeeder`。骨架尚未实现时不能正常求解。
5. 第一阶段性能验收先使用两个指定 8-Puzzle，避免把 `problems.txt` 中的 15-Puzzle误当作第一阶段验收条件；完整测试文件仍保留。
6. `.idea` 个人配置和 `out` 不共享。JDK 安装路径不需要相同；每位成员在交付中记录实际 `java -version`。
